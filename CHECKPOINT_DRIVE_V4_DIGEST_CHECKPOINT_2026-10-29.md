# CHECKPOINT — Drive V4 priority full-scan checkpoint fix

Date: 2026-10-29

## Problem

The priority scanner failed on the large `Kho NCN bigg` shelf while saving `TANGTHU_DRIVE_PRIORITY_STATE_V2`:

`Exception: Argument too large: TANGTHU_DRIVE_PRIORITY_STATE_V2`

The immediate cause was `full_rows`: the full fingerprint scan accumulated every metadata row in Script Properties. Apps Script Script Properties cannot safely hold a large shelf's complete row list in one property value.

Observed shelf at failure:
- `Kho NCN bigg`
- Level 3
- 13,419 items
- 9,331,809,315 bytes
- quick scan completed in about 7 seconds
- full scan exceeded the 45-second per-shelf budget and attempted a checkpoint

## Decision

Do not store `full_rows` in Script Properties.

The full scan now computes an order-independent 256-bit accumulator from SHA-256 of each normalized metadata row. The checkpoint stores only:
- `full_scan_queue`
- `full_visited`
- `full_digest_work` (64 hex characters)
- `full_count_work`

This keeps the durable checkpoint small while preserving detection of changes to ID, parent, name, MIME type, size, modified time, created time, checksum, and folder status.

## Compatibility

Existing fingerprints generated by the previous sorted-row algorithm remain valid until a shelf actually requires a full scan. On the first full scan after this change, that shelf receives the new fingerprint format:

`<row_count>:<256-bit-accumulator-hex>`

If an old interrupted `full_rows` checkpoint is encountered, it is discarded and the full scan restarts cleanly.
