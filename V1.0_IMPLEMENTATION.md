Date: 2026-09-15

## Goal

Turn the v0.4 scanner/catalog prototype into the first complete usable product without replacing the working Drive scanner or changing the locked architecture.

## Completed

### Catalog

- Google Drive shared-folder registration
- Real Drive folder-name retrieval
- Independent Branch display name
- Duplicate root detection
- Recursive scan
- Persistent JSON catalog
- Folder hierarchy preservation
- Hourly refresh
- Manual refresh
- Branch hide/restore
- unavailable state on scan failure
- uppercase `VN` priority

### Web

- Public Branch list
- Recursive Branch/folder browsing
- File metadata
- Filename/checksum search
- No public download route
- Admin registration, rename, hide/restore, refresh
- Basic Authentication

### OPDS

- Root → Branch
- Branch → folder/file
- Arbitrary recursive folder depth
- OpenSearch description
- Filename/checksum search
- Acquisition links using Branch ID + file ID

### Acquisition

Implemented server-mediated streaming:

```text
OPDS client
  ↓
/opds/acquire/<branch-id>/<file-id>
  ↓
validate Branch/file relationship
  ↓
Google Drive API
  ↓
stream response
```

HTTP Range is forwarded to Google Drive so clients can perform partial reads.

Drive identity is not returned to the client.

## Deliberately deferred

These are production hardening rather than core MVP functionality:

- short-lived acquisition tokens
- rate limiting
- request/abuse logging
- per-user authorization
- incremental Drive change tracking
- database index for very large libraries
- ebook metadata/cover extraction

## Validation

Local source validation performed with:

```sh
go test ./...
```

The existing v0.4 tests were preserved and extended for folder ordering, file acquisition validation, and Drive MIME classification.
